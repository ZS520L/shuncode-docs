# 记忆

:::tip[核心]

**项目即记忆。** 不用刻意追求外置记忆。

记忆都是有损的。记忆的目的是省 Token。**ShunCode 用户 Token 自由，不需要。**

:::

## 为什么很多产品要做「记忆」

上下文有长度，API 按 Token 计费。把聊天摘要、向量库、长期备忘塞到模型外面，下次少喂一点字，账单好看一点。这是省钱方案，不是更懂你。

压缩就会丢细节。谁决定留什么、扔什么，那次「记忆」就已经有损。隔几周再取出来，对不上当时的代码，比没有记忆更误导。

## 项目才是完整记忆

真正能跨会话、跨人、跨工具留下来的，是项目（工作区）里的东西：

- 代码和注释
- 提交说明、文档、约定
- 失败过的记录、你愿意写下来的决策

模型每次打开工作区，读的就是这份记忆。不经过另一层摘要，也就没有那一层损耗。

**该记住的，写成项目里的文件；** 不要交给一个你看不见、也难以核对的记忆库。

## 为什么 ShunCode 不推外置记忆

Chat 模式自己填 Key，免费模型和接口福利很多，Token 不是瓶颈。省 Token 的记忆，对「Token 自由」的人是假需求。

Bridge 对面的 Agent 同样在读你的本机项目。项目在，记忆就在；项目不在，外置记忆也救不了。

:::info[怎么做就对了]

把重复要交代的话写成 Skill 或项目里的规则。把结论写进文档和代码。不要为了「它还记得我」再养一套记忆系统。

:::
